# 研究与交付检查

本规则用于提出研究结论的模型。整理已有图面时，先保护现有研究材料，不要求无关的论文格式重做。

## 建模依据

先记录研究问题、系统边界、时间单位、内生反馈、外生驱动、关键变量、参数来源与取值理由。区分统计初值、文献依据、校准量、时滞和敏感性范围；不能用“AI估计”代替来源。方程和每条因果边应有机制或数据依据，极性不能只根据名称判断。

存量明确初值和流入/流出，流率的单位为存量单位/时间。方程量纲检查以原生 Units Check 为准。缺少单位时补真实单位，不统一填写 Dmnl。

## 行为验证

历史期与预测期使用同一套内生状态方程连续运行。真实历史观测可以作为明确外生驱动或外部对照，但不能把研究对象的实际轨迹写回存量来伪装历史再现。若模型本来就是外生回放或混合预测，应如实命名并说明边界。

验证至少包括初值、极端条件、守恒关系、步长敏感性、历史行为比较、参数敏感性和政策传导方向。拟合好不自动证明结构正确。误差指标、数据来源、参数范围、仿真后端和时间设置应可复现。

研究需要派生指标时，根据当前方法定义变量、归一化锚点、权重与公式；不预设某个案例的指标体系。带单位量与同单位参数相减或相除，量纲需验证。若指标声称来自动态模型，应从该模型的变量连续计算，不能混入另一套统计结果后称作同一输出。

## 工具与人工检查

`academic model.mdl --references refs --spec research_spec.json` 可发现部分缺项与可疑结构。机器规则只提供筛查，不能证明引用真实、机制成立或研究合格。报告中保留例外原因，不使用无意义反馈或零系数消除警告。默认对历史/外部数据输入给出核对提示；明确要求严格内生检查时加 `--strict-endogenous`。使用 `--require-derived` 时必须逐项指定 `--derived-output`；只选择当前研究确实要求依赖模型计算的指标。旧参数 `--require-coupling` 与 `--coupling-output` 保留为别名，不再推断固定指标名或公式。

文献和数据必须实际阅读与核实。模型图来自真实 MDL 原生导出；仿真曲线要能回指保存的数据与运行记录。无法原生运行的情况明确写出，不能把 Python 成功当作 Vensim 验收。

## 成稿与交付

正文连贯呈现问题、边界、机制、参数依据、验证、情景和局限。不要把 AI 生成、软件操作、返工过程写成研究方法。表格、图例、变量名、单位、有效数字统一；结论限定在模型边界和参数范围内。

正式文档保留可编辑源稿；PDF 做文本、字体、页数和视觉检查。交付目录只包含约定的模型、数据、结果图、必要报告和复现说明。调试预览、缓存、重复旧版本不混入交付；用户文件不擅自删除。作者署名和许可写在文档中，不干扰模型结构图。
