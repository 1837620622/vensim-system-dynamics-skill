# 情景、策略与耦合仿真规范

本手册描述如何把一个研究任务拆成可复现的基准、策略、机制、独立模块和耦合实验。文中的“基准情景”“核心企业策略”“数字化作用”“独立博弈”“耦合仿真”只是常见的任务类型，不是固定变量名、固定参数或固定方程。实际名称、单位、时间范围和参数必须来自当前任务资料。

## 先定义边界，再写方程

每个任务先建立一份情景登记表，至少记录：

| 项目 | 必须明确的内容 |
| --- | --- |
| 情景标识 | 稳态基准、策略变化、机制检验或用户指定的名称；名称必须唯一 |
| 模型范围 | 当前 MDL、View、变量清单和源文件 SHA-256 |
| 时间设置 | INITIAL TIME、FINAL TIME、TIME STEP、SAVEPER 及时间单位 |
| 参数变化 | 只覆盖数值常量；覆盖前后值、来源、单位和变化依据 |
| 观测输出 | 变量、单位、保存时刻、统计量和图件配置 |
| 随机性 | 随机分布、种子、样本数和抽样边界；没有资料时不自行添加随机项 |
| 结论边界 | 比较结果、结构诊断、敏感性或机制证据；不把情景比较写成预测证明 |

情景名只用于报告和图例。方程引用必须使用当前模型中的原生变量名；新建模型优先使用中文变量名，用户明确指定英文时才使用英文。已有模型保留原名，不为了满足语言偏好而改写方程、影子变量或数据接口。

## 基准与策略实验

基准运行使用当前 MDL 的原始常量、初值和时间设置，单独保存 `baseline.csv` 或 `series.csv`，并记录完整运行元数据。策略情景只通过显式 `params` 覆盖允许的数值常量；不能通过参数间接改变时间控制、存量方程或反馈结构。策略可以表示组织决策、企业行为、数字化投入、治理强度或其他领域因素，但这些词不应成为代码中的特殊分支。

推荐的最小 `scenarios` 结构如下；变量名和数值必须替换为当前资料：

```json
{
  "mode": "scenarios",
  "variables": ["目标输出"],
  "scenarios": [
    {"name": "基准情景", "params": {}},
    {"name": "策略情景", "params": {"当前模型常量": 1.0}}
  ]
}
```

每个情景从同一源 MDL 重新初始化。输出必须携带模型哈希、有效时间网格、后端、参数和保存点数量；任一运行期间模型发生变化、保存网格不一致、终点未被保存或结果含非有限值，整组结果不得发布。`summary.csv` 的 `Final` 只在最后保存点等于 `FINAL TIME` 时写出，不能用最后一个较早保存点冒充终值。

## 机制、数字化与独立博弈模块

当问题要区分“某项作用是否存在”与“整体策略效果”时，先把机制变量和决策变量分开：

1. 在资料支持的范围内声明作用方向、时滞、单位和方程位置；非单调或证据不足的关系保持未标注并进入反馈审查。
2. 运行去除机制、基准机制和加入机制的独立情景，保持其他参数、时间网格和随机种子相同。
3. 如果存在博弈或行为模块，先独立运行它的状态、收益或策略比例，确认初值、边界和守恒关系，再把经过单位核对的输出作为耦合接口。
4. 独立模块的结果只能说明该模块在给定输入下的轨迹，不能直接替代完整系统的策略结论。

“核心企业”“数字化”“平台”或其他角色只是标签。代码和模板不得通过变量名猜测角色，也不得为某个旧案例自动补充策略、收益或采纳率。

## 耦合仿真

耦合实验必须显式记录接口，而不是把两个模型的同名变量静默拼接。每条接口至少包含：

```text
源模块、源变量、源单位
目标模块、目标变量、目标单位
方向与转换关系
时间对齐规则（同一保存点、滞后一阶或其他有依据的规则）
初值与缺失值处理
是否允许反馈回写、迭代次数和收敛阈值
```

执行顺序为：先分别检查各模块 → 对接口做名称、单位、时间网格和范围检查 → 运行无耦合基准 → 运行单向耦合 → 如资料明确存在反馈，再运行有界的双向耦合。每一层结果使用独立目录和清单，不能把独立轨迹覆盖为耦合轨迹。双向耦合必须报告每个时间点的迭代是否收敛；不收敛时保留诊断文件并停止发布结论。

耦合接口不得改变源 MDL 的方程区。对于需要外部时间序列、数组、宏、复杂查表或原生数据连接的模型，先在支持该功能的 PySD 或 Vensim 环境中运行，再把导出的、带哈希和单位清单的序列作为输入；内置标量 Euler 引擎不会假装支持这些高级语义。

## 结果对照与图件

基准、独立模块和耦合模块使用相同的时间单位和明确的变量映射。结果图默认彩色、白底、无标题、无图号、无水印；图例只显示真实情景名和变量名，不把“AI 生成”“调试”“模型哈希”等工作流信息放到图内。每个模块和情景都保留可追溯的 CSV、JSON 清单和源模型哈希，图件从这些真实结果生成。

Python 内置 Euler 适合快速批量运行；PySD 可作为同一 MDL 的逐点交叉检查。两者一致仍不等于原生 Vensim 的逐点证明；涉及原生特殊函数、外部数据或 DSS 专有优化时，必须单独记录原生验收状态。

## 发布前门禁

- 变量名、方程、单位、流向、影子身份和反馈极性均来自当前资料并通过结构检查。
- 基准与每个策略/机制情景使用同一模型哈希，参数覆盖没有偷偷改变时间控制。
- 独立与耦合输出分目录保存，接口映射、单位、时间对齐和收敛记录齐全。
- 结果图中的曲线、颜色、编号和图例与 CSV 一一对应，不添加无依据的注释。
- 论文或报告中的结论明确区分情景比较、机制证据、敏感性和预测；没有资料支撑的角色、参数或行为不自动生成。
